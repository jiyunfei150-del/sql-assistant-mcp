SQL 助手：怎么用 MCP 接数据平台

经验总结 · 2026-11-17 · 基于 SQL 助手 2026-10-08 上线以来的实现与排障

一句话：SQL 助手不连库、不存元数据，所有能力都通过 MCP 向数据平台要。我们自己只写了一层「平台会话」，对平台公布的工具做三件事：挑出能开放的，藏起身份参数和执行通道，补上两个平台没有的工具。模型只和这层会话打交道，权限永远等于提问人本人在平台上的权限。

4从工具声明里删掉、调用时由服务端注入的身份参数
2自己合成的工具：show_create_table、submit_answer
24 步 / 300 秒单轮预算上限，到点只受理交卷

全景：中间那层会话做了什么

模型看不到 MCP，只看到会话层整理过的工具清单；平台看不到模型，只收到服务端补好身份的请求。

模型（GLM）

  • 收到 function calling 格式的工具声明（OpenAI 兼容接口）
  • 只决定调哪个工具、传什么业务参数
  • 最后必须调 submit_answer 交卷
⇄工具调用

平台会话 PlatformSession（我们写的）

挑白名单选工具；按项目是否开通洞察挂增强工具
藏删身份参数；已选定项目时连 project_id 也删；执行通道不出现在清单里
补合成读建表语句、交卷两个工具；结果缓存、并发读、重试
⇄MCP / SSE

数据平台 MCP 服务

  • 按 account_hash_id 圈定账号和权限
  • 公布工具声明（list_tools）
  • 搜表、读结构、规范、EXPLAIN 校验、执行

一轮怎么跑

一次提问就是一条 MCP 会话：开会话 → 准备上下文 → 工具循环 → 交卷，结束时关闭会话。

  1. 服务端换身份

    飞书用户 ID 经网关换成平台 user_id，再按项目名取出 account_hash_id（详见下文「身份怎么来」）。

  2. 服务端 → 平台建 MCP 会话

    sse_client + ClientSession.initialize()，account_hash_id 拼进 SSE 地址，这一步就确定了账号和权限。

  3. 服务端 → 平台取账号上下文：get_key_info

    拿到数据源、库类型、名下项目和各项目是否开通洞察。只有一个项目时直接选定；用户点名的项目不在名下就当场报错，并列出可选项目。

  4. 服务端 → 平台取工具声明：list_tools

    按白名单筛选，删掉身份参数，生成给模型的工具清单。get_table_info、validate_sql 两个必需工具缺一个就停，不带病上路。

  5. 服务端 → 平台预读

    先读一次 get_sql_rules，再预读用户在页面上选中的表（最多 5 张），都放进开场材料，模型不用再查。

  6. 模型 ⇄ 会话 ⇄ 平台工具循环

    模型搜表、读结构、读建表语句、自查 EXPLAIN。同一批里的只读调用并发执行（最多 4 路），同工具同参数的重复调用直接拦下。

  7. 模型 → 会话交卷：submit_answer

    守门检查不通过就把原因作为工具结果退回给模型修改；通过后交付，有权限缺口时附上申请链接。

边界由这张清单决定，不靠提示词约束。

身份怎么来：飞书用户 → account_hash_id

MCP 只认 account_hash_id，我们要把「谁在提问」可靠地换成它。按数据部的接入契约实现。

三跳

  • 飞书短 user_id → 网关查用户，按 union_id 精确匹配，得到平台 user_id
  • 平台 user_id → 网关查名下数据源项目，项目名先精确匹配，没有再包含匹配
  • 取该项目第一个非空的 ds_hash_ids[].value 作为 account_hash_id

结果在进程内缓存 10 分钟，网关超时 10 秒。

三条铁律

  • 用户匹配到 0 条或多条都判失败，不猜
  • 项目匹配上但 hash 全空 = 该用户在这个项目下没有账号，如实告知，不向用户索要 hash
  • hash 只在服务端流转，模型和前端都看不到

① 建会话：身份拼在地址上，https 换自签证书工厂

@contextlib.asynccontextmanager
async def open_session(account_hash_id):
    url = f"{MCP_URL}?account_hash_id={quote(account_hash_id)}"
    headers = {"X-API-Keys": keys} if keys else None      # 公网端点才需要
    kw = {"httpx_client_factory": insecure_factory} if url.startswith("https://") else {}
    async with (sse_client(url, headers=headers, **kw) as (read, write),
                ClientSession(read, write) as session):
        await session.initialize()
        yield session

② 改造工具声明：直接用平台的 inputSchema，只删不写

ALWAYS_INJECTED = ("account_hash_id", "key_index", "question", "model_name")

for tool in (await mcp.list_tools()).tools:
    if tool.name not in wanted:                         # 白名单：BASE_TOOLS (+ INSIGHT_TOOLS)
        continue
    schema = deepcopy(tool.inputSchema)
    hidden = list(ALWAYS_INJECTED) + (["project_id"] if project_selected else [])
    for k in hidden:
        schema["properties"].pop(k, None)
    schema["required"] = [r for r in schema.get("required", []) if r not in hidden]
    tool_specs[tool.name] = {"description": tool.description, "schema": schema}

③ 调用时注入：模型传的身份一律丢弃，项目只放行名下的

def _args(name, args):
    clean = {k: v for k, v in args.items() if k not in ALWAYS_INJECTED}
    clean.update(identity())                            # 服务端持有的真实身份
    if not takes_project[name]:
        clean.pop("project_id", None)
    elif selected_project:
        clean["project_id"] = selected_project.id       # 已选定：强制覆盖
    elif int(clean.get("project_id", -1)) not in allowed_ids:
        clean.pop("project_id", None)                   # 名下没有：不传，平台按有权限的库查
    return clean

④ 合成工具 show_create_table：在执行通道上包一层

name = await resolve_table_name(full_name)             # 按项目目录核对真实全名，不猜库前缀
sql  = f"SHOW CREATE TABLE {name}"                    # 程序拼 SQL，模型只给表名
await validate(sql)                                     # 平台契约：先校验
job  = (await call("submit_sql_query", sql)).job_id
while not timeout(30):                                  # 轮询：100 排队 / 429 限流 / 200 完成
    r = await call("get_sql_query_result", job)
    if r.status == 100: sleep(1.5); continue
    if r.code   == 429: sleep(5);   continue
    return r.ddl

交卷与守门

交付做成工具调用后，程序能在交付前检查，而不是等模型说完再补救。

本地事实检查（不通过就退回）

  • 只读：必须以 SELECT / WITH 开头，语法树里没有写入
  • 一段只放一条语句；不能有 ${}、{{}} 之类的占位符
  • 表名写全 库名.表名，且本轮读过结构
  • 用到的字段在已读结构里存在
  • 平台 validate_sql 通过

只提示、不退回

  • EXPLAIN 里的预估扫描行数；没按分区列过滤，可能全表扫描
  • 明细查询没加 LIMIT；说明里的时间窗与 SQL 不一致
  • LEFT JOIN 反连接后取右表列，这些列恒为空

是不是问题取决于用户意图，所以随答复交给用户，模型自查时也会看到。

退回的上限

同一份提交连续两次被退回，本轮停止，向用户说明原因，不交付没通过检查的 SQL。

防打转：预算写在 MCP 调用层

数字都来自线上实测后的调整，统一在工具循环里处理，不依赖模型自觉。

机制阈值触发后
重复调用拦截同工具同参数不请求平台、不显示在页面上，回一句「结果见前面」
同参数连续失败2 次本轮停止，不再耗步数
提醒收手剩 6 步，或已用时 150 秒插一条提示：停止探索，用已读材料作答
只受理交卷剩 3 步，或已用时 300 秒除 submit_answer 外的调用一律不执行
步数上限24 步（含被退回的提交）停止，并列出已探索过的表
模型不调工具直接说话催 2 次仍不按协议交卷就结束本轮
单次生成超时120 秒；连续 2 次第 1 次转入收尾，已读的表不作废；第 2 次停止

可以带走的经验

  1. MCP 服务端就是能力边界，接入方做「挑、藏、补」。挑出该开放的工具，藏起身份和危险通道，补上业务需要的合成工具。
  2. 工具声明直接用服务端的，只删不写。公布的就是校验的；平台加参数、改说明，我们不用改代码。
  3. 身份永远不经过模型。声明里删掉、调用时注入、模型传了也丢弃。这是用 MCP 做多用户服务最省心的权限方案，不用自建权限体系。
  4. 危险能力包成窄工具再给。执行通道不直接开放，包成只能跑 SHOW CREATE TABLE 的合成工具，参数只有一个表名。
  5. 让交付也走工具调用。有了 submit_answer，守门才有抓手，退回原因也能作为工具结果回给模型。
  6. MCP 调用失败要分级处理。数据源抖动重试一次；单个工具失败回给模型；权限被拒降级处理；只有平台整体不可用才停下这一轮。
  7. 平台的「通过」不等于正确。平台校验是必要条件，事实检查要自己补。
  8. 防打转写在调用层，不写在提示词里。重复拦截、步数和时间预算都由程序执行，换模型也照样生效。
